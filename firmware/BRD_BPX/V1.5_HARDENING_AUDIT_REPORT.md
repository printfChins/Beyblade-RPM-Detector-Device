## 二、已修改的問題與程式位置

### P1-A：連續額外下降緣導致 SP/MAX 誤判

**修正狀態：PASS（針對本報告列出的雜訊形態）**

- 修改 `BRD_BPX/brd_measurement.cpp`：在既有 5 點週期中位數之外，對**首次有效值與新 MAX 候選值**加入完整週期視窗一致性檢查。正常減速及兩點式結束判定仍維持既有機制。
- 修改 `BRD_BPX/brd_config.h`：新增 `RPM_PEAK_WINDOW_JITTER_PERCENT=25`、`RPM_FAST_STARTUP_THRESHOLD=20000`，高轉首次取樣須滿 5 個一致週期。
- 修正較快有效脈衝的辨識速度：已建立可信 MAX 後，連續 4 個一致的高速週期可更新新 MAX，不必等待舊的慢週期完全離開 5 點視窗。
- 新增測試：原始 5000µs／12000 RPM，連續插入 `1300+1300+2400µs` 和 `1100+1100+1100+1700µs` 雜訊；起始即有雜訊、正常逐段加速、短暫連續 4 圈 30000 RPM，以及 32 點曲線後仍更新 MAX。

**通過結果：** 上述 LOAD 與 AUTO 案例都能保留正確 12000 RPM，或在輸入真實 2000µs 週期時正確更新至 30000 RPM。

**適用限制：** 只看到單一路 GPIO3 Falling 時，若每圈恰巧多一個**完全等距**的假下降緣（真實 5000µs，邊沿變成每 2500µs 一次），韌體無法區別 12000 RPM 的假脈衝與真正 24000 RPM。此項仍為 **XFAIL-01**；須從光學、施密特輸入、EMI 或額外感測資訊解決。對不足 4 個穩定週期的快速高轉峰值，本版可能保守低估。

### P1-B：已裝載 READY 時 SAVE 導致 LOAD 清除、隨後漏測

**修正狀態：PASS**

- 修改 `BRD_BPX/brd_settings.cpp`：儲存前比對舊值與新值的量測模式，只有 `LOAD ↔ AUTO` **真的變更**才要求量測模組重建狀態；電池容量、HOLD、百分比與 AUTO 門檻等非模式設定不再一律重置 LOAD。
- 修改 `BRD_BPX/brd_measurement.cpp`：LOAD 裝載 READY 期間允許設定草稿與 SAVE 命令排入，但真正 NVS 寫入**延後到卸載、完成去抖且不處於 HOLD 解鎖流程後**。開始轉動時仍持續取樣，而不是為存檔中斷。
- 修改 `BRD_BPX/brd_ota.cpp`：OTA policy 另外檢查 Flash 安全窗口，已裝載狀態不允許開始 OTA。
- 新增測試：LOAD READY 期間 SAVE 500mAh、LOAD READY 期間 SAVE 模式切換，均確認沒有立即 Flash 寫入、沒有提早套用模式、能記錄隨後第一發 12000 RPM，並在真正卸載後完成保存。

**對手機端的行為變化：** 如果 LOAD 一直維持裝載，設定的 SAVE 可能維持 `PENDING`；要在卸載後才得到 `SAVED`。這是為避免存檔打斷 RPM 的刻意變更，**不是 BLE 斷線**。

### P2-D：Flash 捕捉空窗

**修正狀態：LOAD READY 的可避免空窗已封鎖；AUTO READY 與競態窗口仍有條件性風險。**

- 修改 `BRD_BPX/brd_measurement.cpp`：讀取實體 LOAD 電位、RAW、STABLE、HOLD 解除要求與狀態，禁止在明顯已裝載或 LOAD 去抖途中進入 Flash 寫入。
- 修改 `BRD_BPX/brd_ota.cpp`：OTA 的前置政策與 Flash 實際安全條件保持一致。
- **不能保證零空窗**：Flash 作業開始後突然發生的實體脈衝，或 AUTO READY 允許寫入設定的情況，仍可能錯過首次 Falling。見 **XFAIL-02**。

### 原有未修改的行為

- 保留 BLE BBP 通訊封包格式、BLE Notify 節流與失敗重試，未自創不相容 ACK。
- 保留電池充／放電演算法及 200／250／300／500／1000mAh 設定。
- 保留 OLED 字型、即時 SP／MAX、LOAD/AUTO 模式、HOLD 與現有操作流程。
- 沒有修改 `partitions.csv`，也沒有產生未經實機編譯的 BIN。

## 四、測試方式與重現命令

從完整 ZIP 的 `BRD_BPX/` 目錄執行：

```bash
python3 tests/run_host_tests.py
```

此入口依序執行既有主機測試、`run_fix_regressions.py`（80 組）和新增 `run_v15_hardening.py`（18 組 PASS、2 組 XFAIL）。用 GNU g++ C++17 編譯，部分測試使用 ASan / UBSan；硬體層使用 GPIO、NimBLE、NVS、OTA 模擬替身。實際裝置整體安全性不能僅靠這些測試確認。

可以獨立執行新增的測試：

```bash
python3 tests/run_v15_hardening.py
```

**結果摘要：** 原有量測修正 80 PASS；本次 18 PASS；2 XFAIL。全部新增通過項目都有原始測試碼，可直接執行；詳細輸出附於 `tests/TEST_RESULT_V1.5.txt`，原始完整主機 log 同時獨立交付。
