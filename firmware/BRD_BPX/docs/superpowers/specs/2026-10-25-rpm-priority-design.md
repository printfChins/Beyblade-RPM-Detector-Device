# RPM 優先修正設計

使用者要求：RPM 擷取及計算最高優先，OLED 次之，其餘功能不得中斷基本量測。

## 決策
- 採原生 ESP-IDF IRAM GPIO ISR，使用 esp_timer_get_time() 取得時間；避免 Arduino 非 IRAM ISR wrapper 在 Flash 寫入時停收。
- 正常歷史及設定保存不關閉 ISR 捕捉，也不清除保存期間排入的事件；設定 Flash 保存後需等安全窗口才套用。
- HOLD 為顯示狀態，新量測可優先取代舊 MAX。尾段脈衝以安靜 300ms 或新 LOAD 裝載事件重新武裝，避免重複計次。
- 完成資料與下一輪 Session 分離，避免 600ms BLE 發布延遲抹掉已完成資料。
- 主迴圈優先處理量測，再 OLED；每個背景模組前後服務量測，每輪限制一個 Notify 嘗試。
- RPM Queue 1024 格，小塊快照降低 critical section 時間；溢位不得把缺失邊沿算成正確週期。
- 新增 ISR 收取、停用、排入、滿列、最後事件時間與狀態診斷。
- 低電/ADC 故障保護保留；使用者主動 OTA 屬維護模式，明確暫停量測，取消/失敗/逾時必須恢復。
- 維持 V1.2、GPIO、BBP/設定/OTA UUID 及既有封包格式；不修改量測百分比及預設門檻，不憑空增加峰值濾波。

## 取捨
只加診斷無法滿足優先級；任意逾時重掛中斷可能破壞正常維護。選擇持續擷取與背景交易分離。硬體時序仍需實機驗證，不能由 host 測試保證感測器訊號或射頻環境。
