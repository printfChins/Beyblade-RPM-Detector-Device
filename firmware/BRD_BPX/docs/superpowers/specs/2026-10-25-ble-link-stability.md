# BLE 傳送後斷線：修正規格

使用者回報測試時傳送一次藍牙資料後自動斷線，延續既有修正工作；RPM > OLED > 其他功能的要求仍有效。

已確認程式有兩條主動斷線路徑：BBP 命令佇列滿、Notify 失敗達 1500ms。尚無實機 GAP reason／重啟紀錄，不能宣稱已確認使用者現場根因。

最小方案：保留連線，佇列滿只拒絕額外命令並記錄；已接受命令不刪除。Notify 失敗保留同一份快照、同一頁，隔 100ms 重試，成功後恢復 10ms 分頁節奏。不忙等、不改 RPM、OLED 或 Flash 路徑，不提高 BLE 優先級。真正斷線或取消訂閱仍作世代隔離。

其他方案：只延長斷線逾時仍會在塞車時斷線；改成 BLE 優先或同步阻塞重送不符合 RPM 優先要求。故採最小方案，由執行者在既有授權修正範圍內決定。

保留 V1.2、UUID、17-byte 封包、12 頁順序、32 筆命令容量、每輪最多一次 Notify。僅新增唯讀斷線診斷，不新增封包欄位。拒絕第二個連線、低電／ADC 保護及使用者設定的充電停用策略繼續保留。

驗證須覆蓋：先成功一包再失敗 >1.5s；40 筆突發命令；失敗重試節流；RPM 延後 BLE >1.5s；真實重連／取消訂閱清掉舊傳輸；RPM 在 Notify 失敗期間持續計算。完整 host suite 要通過；無 ESP32 目標工具鏈或實機時不得聲稱已證明 RF／控制器／電源重啟問題解決。
