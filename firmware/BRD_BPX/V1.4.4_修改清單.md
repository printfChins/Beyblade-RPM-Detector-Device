## 程式位置

- `BRD_BPX.ino`：`#include` 區新增 `brd_ble_identity.h`；`setup()` 在 `brd_settings_begin()` 後呼叫 `brd_ble_identity_begin()`；`loop()` 在原 `brd_settings_update()` 後呼叫 `brd_ble_identity_update()`。不修改原 RPM/ADC/OLED 呼叫順序。
- `brd_config.h`：定義版本、預設名稱與新 GATT UUID；`brd_hold_limits.h` 集中設定 HOLD 上下限與預設 2500ms。
- `brd_settings_model.h/.cpp`：`Values` 最後新增 `hold_ms`，`Parameter` 新增 ID06；容量驗證接受 250；v3 儲存 20 bytes、舊版 16 bytes 相容；20-byte 回覆使用 Flags bit5/bit6 顯示 250mAh。
- `brd_settings_ble.cpp`：於原設定 Service 的 GATT 建立區新增 UUID 0005～0009。實際容量/HOLD 由主 loop 建立受 critical section 保護的 4-byte 快照，避免 BLE callback 讀寫設定模型。
- `brd_ble_identity.cpp`：名稱 GATT callback 僅寫 RAM 待處理字串；主 loop 於安全量測窗口保存獨立 NVS，讀回一致才生效。已連線時不強制斷線。
- `brd_bbp.cpp`：BLE 初始化與 Scan Response 使用保存名稱；斷線且歷史/設定儲存安全後才重新廣播。eFuse MAC 保留作原 BBP 封包 6-byte UID。
- `brd_measurement.cpp`：HOLD 使用 `brd_settings_get().hold_ms`；原 WAIT/READY/HOLD/RPM 的切換流程保留。
- `brd_battery.cpp`：不需修改，原先已使用 `brd_settings_get().battery_capacity_mah` 動態計算充電 SOC。新增 250 容量後直接得到 90 秒/1%。

## 執行/驗證

在主機開發環境執行：

```bash
cd BRD_BPX
python3 tests/run_host_tests.py
```

已通過模型、NVS、動態 HOLD、名稱保存/恢復、GATT、充電 SOC、AUTO/LOAD、OTA、BBP Notify、歷史、OLED 與安全窗口等主機測試。HTML 內建 JavaScript 已通過 Node 語法檢查。

**限制：** 目前執行環境沒有 Arduino-ESP32 編譯工具鏈，因此尚未編譯 ESP32-C3 目標韌體 `.bin`，也尚未在實體裝置進行 BLE 連線及充電計時驗證。為避免誤燒，本包已移除上傳 ZIP 內舊 V1.4.3 的 `build/` 和 `.bin`。

## 燒錄設定

- Arduino IDE 開啟 `BRD_BPX/BRD_BPX.ino`。
- Board：`ESP32C3 Dev Module`；CPU Frequency：`80 MHz`；Flash Size：`4MB`。
- 依上傳專案編譯選項保留原有 NimBLE-Arduino 2.5.1、Arduino-ESP32 及分割區設定。
- **Erase Flash：None**，保存原本設定與歷史。未更新前建議先備份重要設定。
- 更新韌體後透過 `tools/BRD_BPX_BLE_Config.html` 或自行連接新的 GATT 特徵驗證。

## 安全性提醒

目前沿用原專案的 BLE 安全策略；新設定特徵並未額外強制配對驗證。若產品預計公開販售，建議增加 BLE bonding、權限驗證或寫入解鎖機制，避免附近裝置未授權修改設備參數與名稱。
