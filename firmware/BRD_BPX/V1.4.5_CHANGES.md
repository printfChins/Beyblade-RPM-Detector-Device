# BRD BPX V1.4.5 修改清單

解壓後直接開啟 `BRD_BPX/BRD_BPX.ino`。所有韌體 `.ino`、`.cpp`、`.h` 與 `partitions.csv` 位於同一層。主程式無新增片段，完整檔案清單見 `FILE_MANIFEST.txt`。

| 專案內檔案 | 變更位置與用途 |
|---|---|
| `BRD_BPX/brd_measurement.cpp` | [新增] `confirm_period()` 確認週期後才送入 OLED、MAX 與 BLE Session。 [修改] `check_launch_threshold()` 連續兩次達百分比門檻才結束。溢位後重新累積完整窗口。 |
| `BRD_BPX/brd_config.h` | [新增] `RPM_PERIOD_FILTER_SIZE`、`RPM_PERIOD_STARTUP_COUNT`、`RPM_FINISH_CONFIRM_COUNT`。 [修改] `PROJECT_FIRMWARE_VERSION` 設為 `V1.4.5`。 |
| `BRD_BPX/brd_bbp.cpp`、`BRD_BPX/brd_bbp.h` | [修改] `load_storage()` 在歷史無法驗證時保留原 NVS 資料並使用 RAM。 [新增] `storage_read_only` 韌體診斷。 [刪減] 移除更名時呼叫 `brd_bbp_stop()` 的路徑。 [新增] `refresh_advertising_name()` 更新 GAP 名稱與 Scan Response。 |
| `BRD_BPX/brd_bbp_session.cpp` | [修改] `Session::command()` 的 `0x75` 分支清除已發布歷史後重設擷取狀態。 |
| `BRD_BPX/tests/` | [新增] `test_measurement_fixes.cpp`、`test_bbp_recovery.cpp`、`run_fix_regressions.py`。集中由 `run_host_tests.py` 執行。 |
| `BRD_BPX/tools/BRD_BPX_BLE_Config.html` | 既有 BLE 參數與名稱設定工具。 |

/* [RPM 結算]
 * RPM 開始後第 3 筆有效週期提供初始估計，取前三筆的最長週期。
 * 建立完整 5 筆窗口後取中位數。高轉持續數圈才能寫入 MAX，
 * 因此孤立一、兩圈的真實尖峰也可能被抑制。
 * LOAD 使用 <=，AUTO 使用 <。無有效脈衝滿 300 ms 可直接結算已確認結果。
 */

/* [歷史恢復]
 * 歷史損壞時，新結果暫存在 RAM，重啟後會清空。
 * 確定可捨棄原歷史時，可用上位機清歷史功能送出既有 BBP 0x75。
 * 保存成功後，新結果可跨重啟保留。保存失敗則在安全窗口重試。
 */

/* [驗證]
 * V1.4.4 的 12,000 RPM 合成波形曾在額外脈衝下誤報 54,545 RPM。
 * V1.4.5 通過同一組參考邊沿間隔及其他脈衝相位測試，最終 MAX 維持 12,000 RPM。
 * 完整主機測試通過，包含 140 個新回歸場景。ESP32-C3 目標編譯及實機驗證待完成。
 */
